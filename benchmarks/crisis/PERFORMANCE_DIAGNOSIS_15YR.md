# 15년 시점 한 달 성능 진단

정식 `benchmarks/crisis/replay_checkpoint.json.gz`를 기존 `CrisisReplay.restore`로 읽고, 정확히 1912-01-01인 것을 확인한 뒤 독립 메모리 세계에서 1912-02-01까지 한 달만 실행했다. 원본 checkpoint와 생산 코드의 hash는 그대로이며, 본 30년 캠페인의 상태·난수·기록에 이 추가 한 달을 섞지 않았다. 작업 스크립트와 원시 계측 파일은 `work/`에 보관했고, 사람이 읽을 수 있는 결과는 `benchmarks/crisis/performance_profile.json`과 `performance_profile.txt`에 복사했다.

기존 projects/economy/NPC/crisis의 하루 계산과 월말 Auditor를 모두 실행했다. Auditor를 빼거나 계산을 단순화하거나 계수를 변경하지 않았다. restore에는 4.36초, cProfile을 켠 한 달에는 24.50초가 걸렸다. 이 시간은 계측 오버헤드와 같은 컴퓨터에서 진행 중인 장기 benchmark의 자원 경쟁을 포함한다. 일별 SQLite 거래와 실제 게임 Ledger 쓰기 비용은 포함하지 않는다. 따라서 24.50초를 계측 없는 게임 속도나 30년 benchmark 속도로 사용하면 안 된다.

## 실제 병목

| 계산 | 호출 수 | 누적 시간 |
|---|---:|---:|
| NPC 전체 tick | 31 | 15.01초 |
| 인물의 알려진 상태 구성 `actor_view` | 110 | 9.76초 |
| 기억의 현재 영향 구성 `effective_memory` | 174 | 6.87초 |
| 사건 전체 tick | 31 | 6.65초 |
| 현지 판단 확인 `_local` | 62 | 5.73초 |
| 통치자 평가 `evaluate_ruler` | 64 | 4.91초 |
| 월말 Auditor | 1 | 1.74초 |
| 메시지 전달 확인 `deliver_due` | 62 | 0.44초 |
| 경제 tick | 31 | 0.39초 |

표는 함수가 호출한 하위 계산을 포함하는 시간이다. 서로 겹치므로 합산하면 안 된다. 공통 `deepcopy`는 재귀 호출까지 약 771만 회, 누적 16.89초를 사용했다. 이 수치는 NPC·사건 tick의 하위 복사와 중복되는 값이다.

숫자의 핵심은 산업 생산 공식이 느린 것이 아니라, 인물이 판단할 때마다 자신이 알고 있는 보고와 기억을 안전하게 복사하고 다시 평가하는 비용이 커졌다는 점이다. 정보 유출과 외부 상태 수정을 막기 위한 분리가 유지되지만, 과거 기록이 늘수록 같은 판단 자료를 만드는 데 더 많은 작업이 필요하다.

측정 당시 활성 사건은 2개뿐이었다. 두 사건은 장기 재정위기와 흉작이었다. 현지 처리 경로는 먼저 인물의 알려진 상태를 구성한 뒤 사건 종류·정보 조건 등을 확인하는 경우가 있어, 이 한 달에도 62회의 현지 확인이 5.73초를 차지했다. 많은 전투나 재난을 계산해서 느려진 상황이 아니다. 전체 메시지 전달 스캔은 비용이 있으나 이번 프로필의 주된 병목은 아니었다.

현재 World를 압축하지 않은 정규 JSON으로 표현하면 30,263,816바이트(약 30.3MB)였다. 이 중 NPC 상태는 약 20.7MB, 사건 상태는 약 7.0MB, 경제 상태는 약 0.6MB였다. NPC 상태 안에서는 최근 판단 설명이 약 8.7MB, 기억이 약 3.5MB, 관계와 그 평가 근거가 약 3.3MB였다. 정식 checkpoint 전체 압축 파일은 약 5.6MB이다. 현재 상태 JSON과 전체 checkpoint는 담는 범위가 달라 압축률 계산용으로 직접 비교하지 않는다.

## 해석과 남은 한계

- 현재 소규모 가상 세계에서는 보존 자료를 다시 읽고 복사하는 비용이 지배적이다. 이는 측정한 사실이며, 전체 메시지 스캔이 주범일 것이라는 초기 추정과는 달랐다.
- 30년의 정상 benchmark 총시간은 별도의 최종 결과를 사용해야 한다. 이번 계측은 정상 실행시간을 대체하지 않는다.
- 실제 SQLite 게임은 일별 현재 상태와 영구 기록을 보존한다. 긴 기록이 쌓인 상태에서 그 추가 비용까지 이 프로필로 측정했다고 주장할 수 없다.
- 국가·지역·인물을 훨씬 늘리기 전에는 알려진 상태/기억의 복사, 반복 평가, 활동 대상 인덱스와 저장 크기의 별도 성능 검증이 필요하다. 사건 가능성이나 Auditor를 생략하는 방식으로 속도를 얻어서는 안 된다.
- 이번 진단에서는 어떠한 최적화도 구현하지 않았다. 독립적인 profiling 월 한 번만 실행했으며 경제 결과·정치 판단·저장 규칙은 그대로다.

공개 결과 파일: `benchmarks/crisis/performance_profile.json`, `benchmarks/crisis/performance_profile.txt`. 원시 cProfile 파일 `crisis_profile_15yr.prof`는 작업 폴더 `work/`에 보관한다. JSON에는 함수별 직접/누적 시간, source hash, 시작·종료 이력 개수, 실제 상태 JSON 크기와 활성 사건 종류를 보관했다.
